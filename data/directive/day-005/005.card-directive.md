### II. ARCHITECTURAL REQUIREMENTS

1. **Directive Path Extractor Helper
   (`apps/worker/src/routes/slackEvents.ts`):**
   - Export helper `extractDirectivePath(prompt: string): string | null`:
     - Inspects prompt for patterns matching `data[/\]directive[/\][^\s\]]+`
       (handling Windows `\` and POSIX `/`).
     - Normalizes backslashes to `/`.
     - Returns clean relative path (e.g., `data/directive/day-001/000.jules.md`)
       or `null` if the prompt does not target a directive.

2. **Durable Object Session Association (`apps/worker/src/RepoBotDO.ts`):**
   - In `RepoBotDO`, ensure session/branch metadata storage allows storing and
     retrieving `directive`:
     - `POST /sessions`: Accepts `{ sessionId, branch, repo, directive }` and
       saves to storage.
     - `GET /sessions/:branch`: Returns the stored metadata for a given branch
       or headRef.

3. **Session Ingress Registration (`apps/worker/src/routes/slackEvents.ts`):**
   - In `processAskJulesPrompt`, after extracting
     `directive = extractDirectivePath(promptPart)`:
     - When provisioning the session and branch (`spec/...`), record
       `{ sessionId, branch: branchName, repo: targetRepo.id, directive }` into
       the DO via `env.REPO_BOT_DO.idFromName('global')`.

4. **Prominent Card Placement (`apps/worker/src/slackBridge.ts`):**
   - In `JulesCardParams`, add optional field: `directive?: string | null`.
   - In `buildJulesStatusCard`:
     - If `params.directive` is provided, insert a prominent Block Kit section
       immediately below the header:
       ```json
       {
         "type": "section",
         "text": {
           "type": "mrkdwn",
           "text": "*DIRECTIVE:* `" + params.directive + "`"
         }
       }
       ```
     - Update fallback preview text to include `[<directive>]` when present
       (e.g., `Jules Update [READY_FOR_REVIEW] [day-001/000.jules.md]: ...`).
   - In `postSlackMergeAnnouncement` (the `#ops-bridge` manual/CAS merge
     announcer):
     - If `directive` is known (or extracted from PR body/title), print:
       `>> FULFILLED DIRECTIVE: data/directive/...` directly above or below the
       `[ORIGIN: ...]` block.

5. **Webhook Handler Resolution (`apps/worker/src/index.ts`):**
   - In the `pull_request` webhook handler (`opened` / `ready_for_review`),
     query the DO or PR body for the branch's associated `directive`.
   - Pass `directive` into `buildJulesStatusCard({ ..., directive })`.

6. **Unit Test Coverage (`apps/worker/test/unit/julesSlackObserver.test.ts`):**
   - Add tests verifying `extractDirectivePath` extracts paths with both
     backslashes and forward slashes.
   - Verify `buildJulesStatusCard` renders the `*DIRECTIVE:*` block directly
     beneath the header when `directive` is passed.
   - Verify fallback text includes the directive snippet.
