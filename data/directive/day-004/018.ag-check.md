The **Overview** page
(`[https://jules.google/docs/api/reference/overview/](https://jules.google/docs/api/reference/overview/)`)
holds the exact four architectural answers needed to eliminate the
`404 Not Found` error:

---

### The 4 Critical Clues to Extract

#### 1. The Service Base URL & Route Prefix

Google developer APIs almost never route through an `/api` directory prefix. On
the overview page, look under **Base URL**, **Root Endpoint**, or **Service
Endpoint**:

- **Host Domain:** Check whether it specifies
  `[https://jules.googleapis.com](https://jules.googleapis.com)`,
  `[https://jules.google](https://jules.google)`, or
  `[https://jules.google.com](https://jules.google.com)`.
- **Path Prefix:** Look at whether the base path is `/v1/` rather than
  `/api/v1/`. If the docs state
  `[https://jules.googleapis.com/v1](https://jules.googleapis.com/v1)` or
  `[https://jules.google/v1](https://jules.google/v1)`, sending requests to
  `/api/v1/sessions` causes Google’s gateway to return an instant
  `404 Not Found`.

#### 2. Authentication Header Convention

Check the **Authentication** section:

- **Bearer Token:** `Authorization: Bearer <API_KEY>`
- **Google API Key Header:** `X-Goog-Api-Key: <API_KEY>`
- **Query Parameter:** `?key=<API_KEY>`

Many Google developer platforms (such as the Gemini API) use `X-Goog-Api-Key` or
query parameters rather than `Authorization: Bearer` when authenticating via
standalone API keys.

#### 3. Resource Identifier & Parent Hierarchy

Look at the HTTP path template listed for **Create Session**:

- **Flat Resource:** `POST /v1/sessions`
- **Hierarchical Resource:**
  `POST /v1/projects/{project}/locations/{location}/sessions`

If the platform adheres to Google Cloud Resource AIPs (AIP-121/AIP-122), calling
a bare `/v1/sessions` without a project/location parent path will produce a
`404 Not Found` because the routing engine cannot determine the tenant project.

#### 4. JSON Payload Casing (`camelCase` vs `snake_case`)

In `apps/worker/src/jules.ts`, the dispatch code currently sends:

```json
{
  "repository": "camp-candor/000.repo-bot",
  "starting_branch": "spec/...",
  "task_description": "..."
}
```

Google APIs strictly follow Google API Style Guides (AIP-127), which mandate
**`lowerCamelCase`** for JSON field names:

- `startingBranch` instead of `starting_branch`
- `taskDescription` or `prompt` instead of `task_description`
- A structured source object, such as:

```json
"source": { "github": { "repo": "camp-candor/000.repo-bot", "branch": "spec/..." } }

```

### Inspect the Reference Directly via Antigravity

Because Antigravity runs in your local environment, you can have it fetch and
inspect the documentation HTML directly to pull the exact endpoint
specifications without guessing:

```markdown
# TASK: Antigravity Documentation Probe — Extract Jules API Endpoints

Execute this Node script in your terminal to fetch the Jules API Reference
Overview and output the Base URL, authentication schemes, and endpoints:

node -e " (async () => { const url =
'https://jules.google/docs/api/reference/overview/'; try { const res = await
fetch(url); const html = await res.text();

    // 1. Search for Base URL / Host patterns
    const urls = html.match(/https?:\/\/[a-zA-Z0-9.-]+\/v[0-9][a-zA-Z0-9_\/-]*/g) || [];
    console.log('>> [DETECTED BASE URLS]:', [...new Set(urls)]);

    // 2. Search for Authentication headers
    const authHeaders = html.match(/(?:Authorization|X-Goog-Api-Key|bearer|api_key)[^<\n]*/gi) || [];
    console.log('>> [DETECTED AUTH HEADERS]:', [...new Set(authHeaders)].slice(0, 5));

    // 3. Search for HTTP Method & Path blocks
    const methods = html.match(/(?:POST|GET|PATCH|DELETE)\s+\/[a-zA-Z0-9_\/-]+/g) || [];
    console.log('>> [DETECTED ENDPOINTS]:', [...new Set(methods)]);

} catch (err) { console.error('Probe failed:', err.message); } })(); "
```

Once you look at the **Base URL** and **Create Session** endpoint in that
document (or run the probe above), you can swap in the verified base URL and
payload format in `apps/worker/src/jules.ts` to clear the 404.
